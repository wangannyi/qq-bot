# 运维指南

本文面向已经完成 [搭建与真实收发验收](setup.md) 的维护者。仓库的安装器不会创建后台服务或计划任务。正式运行的服务名称、调度频率和通知对象由维护者自行确定。

## 1. 启动、停止和健康判断

在同一终端设置正确的 `HERMES_HOME`、数据目录与模型环境，然后执行：

```bash
"$HOME/work/hermes-qq/venv/bin/hermes" gateway run
```

前台运行按 `Ctrl+C` 停止。若自行配置了 systemd 等管理方式，请使用自己配置的服务名称停止并核对进程，避免服务管理器又把手工停止的进程拉起。不要同时启动多个使用同一 profile 的网关。

健康检查需要区分：

1. 进程存活、依赖与索引可读。
2. QQ 认证和长连接正常，心跳有响应。
3. 授权测试群真实消息有接收和答复。
4. 答案与问题、板型、系统版本和引用原文一致。

前三项不能代替第四项。离线检查可用 `scripts/doctor.py`，但不会证明远端连通。连接诊断见 [故障排查](troubleshooting.md)。

## 2. 同步资料

```bash
.venv/bin/python cie-qq-ops/sync_docs.py
```

在正确的数据环境中执行，记录同步统计和失败项。不要让多个同步进程同时写同一个索引。需要周期同步时，先完成一次手动验收，再自行安排调度；调度环境必须与网关一致。

资料获取失败时保留错误，修复来源或网络后重试。不要用旧资料冒充新版，也不要禁用资料不足和来源一致性保护。上游网页内容并未通过本仓库的 MIT 许可重新授权。

## 3. 日报与 FAQ

先预览群问答日报：

```bash
.venv/bin/python cie-qq-ops/daily_summary.py --groups-only
```

需要按本地自然日统计时增加 `--today`。这会读取当前 profile 的会话数据，不创建新的问答。

向已配置的 QQ 目标发送是单独动作，需要显式增加 `--send`；目标由 `--delivery-target` 指定，默认使用 Hermes 的 QQ home channel。实际发送前请确认目标、权限和报告内容，尤其不要将私聊混进群报告。

FAQ 发布是另一个显式动作。只有设置了自己有权写入的 FAQ 仓库，审查候选内容和来源，并理解 Git 分支操作后才使用 `--faq-publish`。候选暂存使用显式 `--faq-stage`；可先使用 `--faq-dry-run` 查看选择与审查结果。不要把 `--faq-auto-approve-if-clean` 加入未经验收的调度任务。使用 `--help` 查看全部参数与目标分支设置。

日报或 FAQ 可能包含用户提问。公开发布前应去除身份信息、私有路径与业务机密，并获得必要授权。

## 4. 备份与恢复

备份前停止使用对应 profile 和索引的写入进程。保存：

- profile 配置、插件与凭据，使用仅维护者可读的存储。
- `QQ_BOT_DATA_DIR` 及单独配置的索引、候选数据库和 FAQ 工作目录。
- 本仓库提交号、Hermes 固定提交与补丁状态，以及依赖版本。

SQLite 数据库使用数据库备份接口，或在所有写入停止后一起保留数据库及其 WAL 等关联文件；不要只复制正在写入的主文件。恢复到独立目录，先运行离线检查，再用受控测试群验收，最后切换正式服务。

## 5. 升级与回滚

不要直接把已配置的 Hermes 更新到任意最新版。当前兼容范围由 [Hermes 锁定文件](../patches/hermes-lock.json) 和补丁文件定义。

升级时保留旧代码和 profile，使用新的专用代码目录、Hermes checkout 和测试数据目录验证。检查脚本应能识别补丁状态，重复运行不覆盖定制内容；本地及适用的 K3 软件回归通过后，再做真实 QQ 验收。无法通过时继续使用旧版本，保存具体失败证据。

本项目不附带原部署的 Codex 自动出题、自动检修、账号登录资料或运行预算，也不会在安装后自动重建这些任务。
