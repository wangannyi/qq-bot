# 用户使用指南

本指南面向已加入机器人所在 QQ 群的用户。机器人由群管理员完成安装和授权；普通提问不需要安装 Python、Hermes 或 NapCat。

## 1. 发出完整问题

在群里 `@机器人` 后写问题。尽量一次提供板型、系统版本、正在做的操作、现象与报错。

```text
@机器人 我使用 K3，系统是 Bianbu 4.0。
部署语音识别时模型加载失败，应该先收集哪些信息？
```

不要发送密钥、完整凭据配置、身份证件、私人聊天或未经脱敏的日志。报错里可能包含用户名、内网地址和令牌，发送前检查。

## 2. 补充和更正环境

推荐 Hermes 路径会暂存同群同用户明确提供的环境。部署问题缺少关键条件时，机器人会请求补充；使用明确的板型或系统版本回复。

```text
更正，板子是 K3，系统是 Bianbu 4.0。
```

默认环境窗口为 30 分钟。引用别人消息中的示例版本不作为你的环境声明。跨群、换账号或开始新的问题时，重新写清环境更可靠。

## 3. 阅读答案和来源

答案包含结论、操作要点或完整命令，以及原文链接。先核对来源适用的板型、系统、软件版本和教程路线，再决定是否执行。

| 回复情况 | 处理方式 |
| --- | --- |
| 有明确适用范围和来源 | 打开原文检查前提，再按自己的环境操作 |
| 只解决问题的一部分 | 保留已核实部分，补充其余材料 |
| 资料不足或需要更多环境 | 提供版本、具体操作、完整报错或官方文档链接 |
| 繁忙、超时、答复暂不可用 | 本次没有得到可靠答复，稍后重新发起完整问题 |
| 内容与原文矛盾 | 向管理员报告原问题、实际答案和对应链接 |

机器人不会在你的设备上执行答案中的命令。软件回归通过也不表示某个相机、模型或驱动已经在你的硬件上运行成功。

## 4. 报告错误

向管理员提供问题时间、原问题、实际答复、来源链接和期望行为。保留原始失败，补充后续验证结果；不要把“收到消息”当作“答案正确”。

故障报告公开前去掉账号、群标识、密钥、网络地址和无关聊天。管理员可按 [故障排查](troubleshooting.md) 检查模型、索引与连接。

## 5. 理解 FAQ 和日报

FAQ 候选和日报由部署者配置。日报会合并关联追问、区分待补充和需要人工处理的问题；这些分类不能替代人工审核。是否发布到外部仓库、是否向群发送日报，由管理员分别决定。

可选独立模块另有 `/帮助`、`/状态`、`/日报` 等管理命令。Hermes 路径的命令由具体部署配置决定，不应假定两条路径的指令完全相同。
