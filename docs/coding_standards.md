# 代码规范

## 1. 保持行为边界

运行代码使用 Python 3.11–3.13。新增配置保留已有默认值，外部动作明确启用。QQ 发消息、模型请求、文档下载与 FAQ 发布在离线测试中使用替身，不依赖维护者机器或账号。

保留来源范围、板型与版本、完整命令、缺证据时的保守回复。来源中出现相同文字不代表来源能够支持任意因果判断。新增行为需要验证正常路径和受影响的边界。

## 2. 配置与数据

机器目录、账号和凭据通过配置提供。示例使用空值或占位符。测试在临时目录创建索引、数据库和 profile，不访问真实登录、消息、预算或发布仓库。

测试涉及时间新鲜度时固定测试时钟或生成相对时间，并单独验证过期保护。不得通过更新预期结果掩盖失效路径。

## 3. 质量检查

```bash
.venv/bin/python -m ruff check . --select E9,F,I
.venv/bin/python -m pytest -q
.venv/bin/python scripts/check_release.py
git diff --check
```

修改安装工具时，在新目录执行安装与离线示例。修改 Hermes 补丁时，针对锁定提交执行补丁检查和所需接入测试。涉及 K3 的变更补充适用软件验证，并说明 PC 专属依赖的覆盖范围。

## 4. 公开发布

只提交本次需要的文本源码、合成测试资料和文档。审查完整差异以及被 Git 跟踪的文件清单。数据库、原始用户问题、令牌、日志、登录数据、私有安装路径和机器专属 systemd 配置不进入发布内容。
