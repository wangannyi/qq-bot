# 故障排查

## 1. 离线示例不能运行

先检查 Python 版本和依赖，再运行：

```bash
.venv/bin/python scripts/doctor.py
.venv/bin/python scripts/offline_demo.py
.venv/bin/python -m pytest -q
```

检查命令使用的是仓库的 `.venv/bin/python`，避免加载系统环境中无关的 pytest 插件。离线示例不需要 QQ 或模型凭据；它失败时先修复本地环境，不通过增加账号权限处理。

## 2. Hermes 补丁不能应用

在新的 Hermes 检出目录检查锁定提交和补丁状态：

```bash
.venv/bin/python scripts/prepare_hermes.py \
  --checkout "$HOME/work/hermes-qq" \
  --check-only
```

不要把补丁强行应用到未知版本或覆盖已有修改。使用 [标准搭建流程](setup.md) 创建新目录；安装工具应识别已应用的补丁，并拒绝不兼容的版本。

## 3. 机器人在线但没有回答

依次核对 QQ 开放平台中的机器人权限、测试群和成员配置、当前 profile 的 QQ 开关与凭据、网关日志，以及实际消息是否 `@` 了正确机器人。

进程 `active` 只证明进程运行，QQ `connected` 只证明连接状态。按消息发送、机器人入站、模型请求、实际回复四个位置定位，不将任一信号当作完整成功。

## 4. 模型或资料不可用

模型凭据只从当前 `HERMES_HOME` 读取。核对 provider、模型名称、base URL 与认证文件一致，避免借用其他 profile 的凭据。

索引尚未建立、同步失败或原文过期时，机器人可能保留资料缺口。按 [搭建流程](setup.md) 主动同步资料；不要关闭新鲜度或来源保护来强迫回答。来源不足也不证明全网没有答案。

## 5. 反复重连或心跳无响应

记录故障时间、ACK 年龄、重连和 Resume 结果。结合相同 socket 的接收队列、发送队列与重传判断故障范围；发送函数返回不代表数据已经被对端确认。

公开恢复措施只在配置的机器人运行范围内启用。它能够更换坏连接，不能修复所有外部链路段。保持真实失败记录，逐次核对恢复后的消息和回执；不要仅凭当前 `connected` 关闭故障。

## 6. 答案有来源但结论不正确

检查来源是否属于同一板型、系统、版本和操作路线，是否将节点职责说明扩写成确定原因，是否把局部示例推广到整个平台。

提交脱敏复现时附原问题、答案、相关来源段及不受支持的结论。新增测试既覆盖错误问法，也保留明确前提下的正常问法；不要把所有回答统一改成拒答。
